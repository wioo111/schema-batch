# 项目现状与上线准备

## 当前仓库状态

当前仓库已经进入桌面工作台阶段，不再只是单脚本原型。

现在的实际结构是：

- `React + TypeScript` 前端工作台
- `Tauri + Rust` 桌面桥接层
- `Python` 批处理引擎

已经完成的主链路：

1. 导入文件或程序内录入数据
2. 配置输入列、输出字段和 Prompt
3. 做输入预览、输出预检和 Ready Check
4. 启动批处理并查看运行结果
5. 导出结构化结果

## 当前仓库定位

项目当前应该以这个身份对外：

> 一个适合普通用户使用的、本地桌面式 LLM 表格批处理工具。

而不是：

- 采集平台
- 网页后台
- 命令行脚手架集合

## 上 GitHub 前最重要的事

当前优先级应该是：

1. 保证首页文档和仓库实际状态一致
2. 清理不该提交的构建产物和缓存
3. 补最小样例和环境变量说明
4. 明确哪些文件是主链路，哪些只是历史参考

## 当前仍待补齐的发布项

- 正式 `LICENSE`
- 最小示例输入输出
- 更完整的安装说明
- GitHub Issue / PR 模板

## 当前保留的历史文件

- `qwen_batch-v2.py`
  - 历史原型，对照参考用
- `task_config.yaml`
  - Python 引擎兼容的旧式 YAML 示例配置

这两个文件可以保留，但 README 必须解释它们不是当前桌面主链路的核心入口。

## 当前不做什么

- 不做爬虫主线
- 不做平台化重架构
- 不做多人协作和 SaaS 化
- 不为未来扩展提前塞进一堆复杂目录

## 一句话判断

当前已经适合整理成公开仓库，但还没到“直接发正式安装包”的阶段。
